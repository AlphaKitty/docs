## 1. 引言

### 1.1 文档目的

本文档定义**公司专家管理系统（Expert Link）**的软件需求规格。目标受众包括产品经理、开发团队、测试团队及业务方（领域行管、HR）。

### 1.2 产品范围

构建一个由"领域行管"驱动、以"内容资产"为核心的专家资源全生命周期管理平台。

**包含**：
- 领域行管配置与权限管理
- 专家调用申请与积分自提双模式表单
- 行管指派工作台与负荷调度
- 专家确认、任务执行与评价打分
- 积分自动核算、行管审核、年度津贴判定
- 专家画像、知识资产库、项目案例库
- 树形目录 + 组合条件专家检索
- 专家生命周期管理（入库审核、出库、批量导入）
- 流程节点监控与飞书消息通知
- 多维度统计看板与积分排名

**不包含**：
- AI 智能推荐引擎（标记为二期/待定功能）
- 移动端原生 App（仅 Web 端）
- 专家日程系统本身的建设（仅对接）

### 1.3 定义、缩写与术语

| 术语 | 定义 |
|------|------|
| 领域行管 | 各技术领域的管理者，负责本领域专家调度、指派、成果审核、积分确认 |
| 专家调用 | 需求方发起、指定或由行管指派专家参与项目活动 |
| 积分自提 | 专家自主提交积分申请，附证明材料，经行管审核后获得积分 |
| 积分项目 | 15 种具体活动类型（技术评审、人才评审、技术支持等） |
| 积分大类 | 积分项目的上层分类：评估评审、问题解决、成果贡献、知识沉淀、团队成长 |
| 贡献范围 | 活动影响范围（跨BG/BG内/BU内等），决定标准积分分值 |
| BG/BU | 事业群/业务单元，公司组织层级 |
| e-HR | 公司人力资源系统，提供人员基础信息 |
| 标准积分 | 系统根据积分项目 + 贡献范围自动计算的基础分值（float，不可调整） |
| 年度津贴 | 专家满足年度积分门槛后发放的津贴，字段值 = 1（发放）或 0（不发放） |
| KDW | 是否为重点客户项目（Key Design Win） |
| 脱敏 | 普通用户搜索时专家姓名显示为"张*三" |

## 2. 产品概述

### 2.1 产品背景与视角

- **业务背景**：歌尔（Goertek）作为大型制造企业，拥有大量技术专家分布在各个 BG/BU。当前专家资源管理处于"人治"阶段——找人靠私交、调度凭记忆、贡献难量化。公司需要建立统一的专家资源全生命周期管理平台。
- **系统位置**：专家管理系统处于公司 HR 体系与业务项目体系之间，上游对接 e-HR 人员系统，下游对接飞书消息推送，是专家资源的调度中枢。
- **上下游依赖**：e-HR（人员信息、部门、职位）、飞书（消息通知）、专家日程系统（冲突检测）[推断]。

### 2.2 产品功能概要

1. **领域行管配置** — 超级管理员绑定各领域管理者，确立调度责任
2. **双模式申请表单** — 专家调用（需求方发起）和积分自提（专家发起），字段按积分项目动态显隐
3. **行管指派工作台** — 负荷热力图 + 指派/改派决策
4. **专家确认** — 接受/拒绝任务，拒绝需说明理由
5. **评价与积分核算** — 申请人打分 → 系统自动计分 → 行管审核确认
6. **内容资产管理** — 专家画像、知识成果、项目案例三大库
7. **专家检索** — 树形目录（领域→子领域→方向）+ 组合条件检索
8. **生命周期管理** — 入库审核、批量导入、出库管理
9. **统计监控** — 参与率、攻关数、满意度、积分排名、及时率
10. **年度核算** — 积分上限控制、任期折算、津贴发放判定

### 2.3 产品约束

| 类别 | 约束描述 |
|------|----------|
| 技术 | 必须对接 e-HR 系统获取人员、部门、职位信息；飞书消息推送；支持 PDF/PPT/JPG/Word 在线预览 |
| 法规 | 专家姓名脱敏展示；内容密级控制（公开/内部/秘密） |
| 组织 | 部门层级截取到 2~3 级（BG-BU）；越南算独立区域；工号为唯一标识（避免重名） |
| 预算/时间 | 一期功能已有框架，需完善；二期功能待排期 |
| 隐含 | 积分规则可能随业务调整，需支持配置化 [推断]；申请表单"建议部分配置可更改，方便后期维护"（REF-01 3.2.2） |

### 2.4 用户特征

| 角色 | 描述 | 技能水平 | 使用频率 | 关键目标 |
|------|------|----------|----------|----------|
| 超级管理员 | 系统运维者，配置领域行管映射 | 高 | 低（配置变更时） | 维护系统基础配置 |
| 领域行管 | 各技术领域管理者，核心调度角色 | 高 | 高（每日） | 科学指派专家、审核成果、核定积分 |
| 部门管理员 | 管理部门维度专家数据 | 中 | 中（每周） | 管理本部门专家信息 |
| 专家用户 | 被调用的技术专家 | 中 | 中（按任务频率） | 接受任务、提交成果、积累积分 |
| 普通用户（需求方） | 发起专家调用，评价专家 | 中 | 中（按项目需要） | 快速找到合适专家、评价反馈 |
| HR 专员 | 审核专家入库信息 | 中 | 中 | 确保专家信息准确合规 |

## 3. 需求

### 3.1 外部接口

#### 3.1.1 用户界面

- **左侧树形导航**：按 内容库 > 领域 > 专家 > 成果分类 层级导航
- **顶部快捷入口**：常驻"发起调用"与"上传成果"按钮
- **行管视角**：侧重"审计与调度"，工作台突出待指派任务和待审核成果
- **专家视角**：个人中心突出累计积分与资产贡献排名
- **脱敏策略**：普通用户搜索仅见"张*三"，指派成功后可见联系方式

#### 3.1.2 软件接口

| 接口 | 对接系统 | 数据方向 | 协议/格式 | 频率 |
|------|----------|----------|-----------|------|
| IF-001 | e-HR | 读取 | 人员信息（工号、姓名、部门、职位、联系方式） | 实时 / 定时同步 |
| IF-002 | 飞书 | 推送 | 消息通知（指派、催办、改派） | 事件驱动 |
| IF-003 | 专家日程系统 | 读取 | 专家忙闲时段查询 | 指派时实时查询 [推断] |
| IF-004 | 项目管理系统 | 读取 | 项目名称、客户代码、产品线、阶段 | 申请时查询 [推断] |

#### 3.1.3 硬件接口

不涉及。

### 3.2 功能需求

---

#### 功能领域 1: 申请表单与动态字段控制

**REQ-FUNC-001** — 申请类别切换

| 属性 | 内容 |
|------|------|
| **标题** | 申请类别二选一：专家调用 / 积分自提 |
| **陈述** | 系统应在申请表单顶部提供"申请类别"下拉选择，选项为"专家调用"和"积分自提"。选择后驱动后续字段的可见性和必填规则变化。 |
| **来源** | REF-02 行3：申请类别下拉选择，从右侧项目选择"专家调用""积分自提" |
| **关联痛点** | PAIN-003（用户不清楚该走什么流程）、PAIN-009（专家代提积分场景不明确） |
| **验收标准** | 1. 默认值为空，用户必须选择 2. 选择"专家调用"后，需求领域、需求人数、指定专家字段可见 3. 选择"积分自提"后，积分大类、积分项目字段可见 4. 切换时不清空已填写的公共字段 |
| **优先级** | P1 |

**REQ-FUNC-002** — 积分大类与积分项目级联选择

| 属性 | 内容 |
|------|------|
| **标题** | 积分大类 → 积分项目二级级联下拉 |
| **陈述** | 系统应提供"积分大类"下拉（选项：评估评审、问题解决、成果贡献、知识沉淀、团队成长），选择后"积分项目"下拉联动过滤，仅展示该大类下的积分项目。 |
| **来源** | REF-02 行3-8：积分大类与积分项目的对应关系 |
| **关联痛点** | PAIN-008（不同活动类型差异大，需要分类引导） |
| **验收标准** | 1. 积分大类共 5 个选项 2. 选择大类后积分项目自动过滤为对应子集：评估评审→技术评审/人才评审；问题解决→技术支持；成果贡献→行业技术洞察/技术成果推广/人才标准建设/专业论文/知识产权；知识沉淀→项目经验沉淀/知识库建设/流程制度建设；团队成长→课程开发/担任导师/担任讲师/行业业务交流 3. 先选大类再选项目，不可跳过 |
| **优先级** | P1 |

**REQ-FUNC-003** — 字段按积分项目动态显隐

| 属性 | 内容 |
|------|------|
| **标题** | 项目基本信息字段按积分项目控制可见性 |
| **陈述** | 系统应根据"申请类别"和"积分项目"的组合，动态控制以下字段的可见性：（1）项目基本信息区（项目部门、项目名称、项目级别、客户代码、产品线、当前阶段、是否KDW、是否迭代产品）仅在"专家调用"及积分自提中的"技术支持"项目下显示，其他积分项目下隐藏；（2）需求领域/需求人数/指定专家/专家列表仅在"专家调用"下显示；（3）贡献范围在部分积分项目下隐藏（行业技术洞察、技术成果推广、人才标准建设、专业论文、知识产权），系统直接使用标准分值。 |
| **来源** | REF-02 行18-28：显示/隐藏标记矩阵 |
| **关联痛点** | PAIN-008（不同活动类型差异大） |
| **验收标准** | 1. 切换积分项目时，字段显隐在 500ms 内完成 2. 隐藏字段的值在提交时不清除（保留草稿） 3. 所有 15 种积分项目的显隐规则与 CSV 矩阵一致 4. "活动地点"在所有类型下均显示（仅必填/非必填差异） |
| **优先级** | P1 |

**REQ-FUNC-004** — 需求方信息自动带出

| 属性 | 内容 |
|------|------|
| **标题** | 从 e-HR 自动带出需求人信息 |
| **陈述** | 系统应从 e-HR 系统根据当前登录用户自动带出：需求人（工号，避免重名）、需求人部门（截取到 2~3 级：BG-BU）、需求人职位、联系方式。需求人支持搜索选择切换（以工号为准）。以上字段全部必填、只读展示。 |
| **来源** | REF-02 行9-14：需求人默认带出用户，@张代富改为工号避免重名；需求人部门系统带出截取到2~3级 |
| **关联痛点** | PAIN-006（缺乏系统数据源，手工填写易错） |
| **验收标准** | 1. 页面加载时自动填充当前用户工号、姓名、部门、职位、联系方式 2. 需求人可按工号搜索并切换 3. 部门字段显示为"BG-BU"格式 4. 若 e-HR 接口超时（>5s），显示"信息加载中"并允许手动输入 [推断] |
| **优先级** | P1 |

**REQ-FUNC-005** — 项目基本信息填写

| 属性 | 内容 |
|------|------|
| **标题** | 项目基本信息区域 |
| **陈述** | 系统应在专家调用申请中提供项目基本信息区域，包含以下字段：项目部门（默认带出需求人部门，可改为公司所有部门，2~3级下拉）、项目名称（多选/输入）、项目级别（下拉：公司级/部门级 + X星级）、客户代码（多选/输入）、产品线（多选/输入）、当前阶段（下拉：P1/EVT/MP等）、是否KDW（是/否）、是否迭代产品（是/否）。全部必填。 |
| **来源** | REF-02 行15-28：项目基本信息字段定义 |
| **关联痛点** | PAIN-006（项目名称、客户代码、产品线数据源待确认） |
| **验收标准** | 1. 项目部门默认值 = 需求人部门，支持修改 2. 项目级别下拉含公司所有可选级别 3. 项目名称、客户代码、产品线支持多选和自由输入两种模式 4. 若存在系统数据源，优先以下拉多选呈现；否则以输入框呈现 [待澄清] |
| **优先级** | P1 |

**REQ-FUNC-006** — 活动需求信息结构化模板

| 属性 | 内容 |
|------|------|
| **标题** | 按积分项目动态切换结构化填写模板 |
| **陈述** | 系统应根据积分项目展示不同的"活动需求信息"结构化填写模板。专家调用场景下：评估评审和人才评审的模板"待设计"；技术支持模板包含：问题现象/不良率、具体矛盾点、实测数据与目标值对比、问题复现条件、已调整/尝试的方案、各方案验证结果、已排除的原因/方向、当前无法突破的卡点。积分自提场景下：所有积分项目使用统一的"成果自述"模板（关联背景、具体交付物、量化数据、实际影响描述）。 |
| **来源** | REF-02 行51-61：活动需求信息结构化文本输入，不同类型单独编写提示 |

| **优先级** | P1 |

**REQ-FUNC-007** — 成果提交简述模板

| 属性 | 内容 |
|------|------|
| **标题** | 积分自提的成果提交结构化模板 |

**REQ-FUNC-019** — 系统自动计算标准分值

| 属性 | 内容 |
|------|------|

| **陈述** | 系统应根据申请时选择的积分项目和贡献范围，自动计算标准分值（float 类型，不可手动调整）。计算规则如下：技术评审—跨BG=0.5分/4次，BG内=0.25分/4次；人才评审—1次1分；技术支持—跨BG=2分，BG内=1分；行业技术洞察—1个1分；技术成果推广—跨BG=3分，BG内=2分，BU内=1分；人才标准建设—编写组长=2分，编写成员=1分；专业论文—国家级核心=3分，省市级=2分，公司内=1分；知识产权—发明专利=2分，实用新型专利=1分；项目经验沉淀—1个1分；知识库建设—1个0.33分（每3个1分）；流程制度建设—主责建设=2分，参与建设=1分；课程开发—主责开发=2分，参与开发=1分；担任导师—14+员工且A/B+转正=3分，14+且B或14-且A/B+=2分，14-且B=1分；担任讲师—公司/专业线≥50人=3分，一级部门≥30人=2分，二级部门≥10人=1分；行业业务交流—代表公司发言=2分，来访/去访分享=1分。 |
| **来源** | REF-02 行215-230：系统自动显示标准分值与贡献范围对应关系 |
| **关联痛点** | PAIN-007（积分计算复杂，手工核算易出错） |
| **验收标准** | 1. 标准分值为 float 类型，保留两位小数 2. 分值字段不可手动编辑 3. 贡献范围隐藏的积分项目直接使用固定分值（如人才评审=1分） 4. 计算结果实时展示在评价页 |

### 5.2 JTBD 分析结果

#### 场景 1: 专家调用（需求方发起）

- **当（情况/触发）**：项目遇到技术难题，需要跨部门专家支持
- **我想要（目标/期望结果）**：快速描述问题、选择合适的领域、提交调用申请，系统自动路由给对应行管
- **这样我就可以（更大的目的/价值）**：让项目问题及时得到专业解决，避免因技术卡点导致项目延期
- **目前替代方案**：通过私人关系打听谁能帮忙 → 微信/电话沟通 → 手工协调时间 → 没有正式记录

#### 场景 2: 积分自提（专家发起）

- **当（情况/触发）**：专家完成了符合积分标准的活动（评审、授课、发表论文、担任导师等）
- **我想要（目标/期望结果）**：选择合适的积分项目、按模板填写成果描述、上传证明材料、提交审核
- **这样我就可以（更大的目的/价值）**：积累年度积分，满足考核门槛，获得年度津贴，证明个人贡献
- **目前替代方案**：线下填表 → 邮件提交 → 人工统计 → 年底统一核算

#### 场景 3: 行管指派

- **当（情况/触发）**：收到专家调用申请，需要为本领域需求匹配合适的专家
- **我想要（目标/期望结果）**：查看本领域所有专家的忙闲状态和能力标签，做出科学的指派决策（或改派更合适的人选）
- **这样我就可以（更大的目的/价值）**：确保任务有人接、接的人合适、核心专家不过载，维护本领域资源健康度
- **目前替代方案**：微信群问"谁有空"→ 电话协调 → 凭记忆和熟悉度分配 → 核心专家总被找

#### 场景 4: 评价与积分核算

- **当（情况/触发）**：专家活动结束后，需要对专家表现进行评价并核定最终积分
- **我想要（目标/期望结果）**：申请人打分 → 系统自动根据积分项目和贡献范围计算积分 → 行管最终审核确认（或调整）
- **这样我就可以（更大的目的/价值）**：公平、量化地记录专家每次贡献，为年度考核和津贴发放提供权威数据
- **目前替代方案**：线下评分表 → Excel 手工套公式计算 → 邮件审批 → 年底汇总

#### 场景 5: 专家内容资产沉淀

- **当（情况/触发）**：专家在项目中产出了有价值的方案、报告、课件、案例
- **我想要（目标/期望结果）**：将成果上传到内容库，关联专家画像，通过审核后全域可检索
- **这样我就可以（更大的目的/价值）**：隐性知识显性化，后续项目可直接复用，避免"重复造轮子"
- **目前替代方案**：保存在本地 → 邮件发给相关人 → 随人员变动丢失

#### 场景 6: 年度积分核算

- **当（情况/触发）**：年底（或自然核算周期），需要判定每位专家是否满足津贴发放条件
- **我想要（目标/期望结果）**：系统自动汇总专家年度积分，按级别门槛（17/18/19级分别10/12/15分）和任期折算规则，判定津贴是否发放
- **这样我就可以（更大的目的/价值）**：公平、高效地完成专家年度激励，避免人工统计的遗漏和争议
- **目前替代方案**：HR Excel 手工汇总各来源积分 → 逐一比对门槛 → 手工裁定
