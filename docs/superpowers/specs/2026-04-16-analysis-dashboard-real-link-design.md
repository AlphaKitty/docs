# 统计分析页真实联动设计

**目标**

将 `AnalysisDashboard.vue` 从占位图表和本地假数据页面升级为真实业务数据分析页，完整打通顶部卡片、榜单、最近匹配记录和图表展示。

**范围**

- 仅修改 `expert-link-frontend`
- 优先复用现有真实接口：`experts`、`projects`、`skills`、`domains` 以及可用的项目-专家关系接口
- 本轮不新增后端统计聚合控制器
- 本轮不伪造历史趋势数据、不生成随机分数、不补统计快照存储

**设计**

1. 数据来源与取数策略
   - 页面进入时并行拉取真实列表数据
   - 不再依赖当前 `stats.service.ts` 中预留但后端未落地的 `/stats/...` 接口
   - 由前端完成聚合和映射，保持统计页可快速落地
   - 项目-专家关系数据来源固定为：
     - 先拉项目列表
     - 再对项目列表逐个调用 `getAssignmentsByProjectId(projectId)`
     - 前端按 `projectId + expertId` 去重，形成全局分配关系集合
     - 若同一 `projectId + expertId` 存在重复记录，保留规则固定为：
       - 优先保留 `startDate` 更晚的记录
       - 若 `startDate` 同时缺失，则保留 `completionPercentage` 更高的记录
       - 若仍无法区分，则保留 `id` 更大的记录
   - 分页口径固定为：
     - 总量类指标优先使用分页返回的 `totalElements`
     - 排行榜、分布图、匹配记录这类需要完整样本的数据，使用“大页拉取”策略，先请求 `size=200`
     - 若 `totalPages > 1`，继续顺序拉取剩余页并聚合，避免统计被首屏分页截断
   - `timeRange` 仅作用于可从现有数据推导出的图表切片或展示模式，不影响基础总量口径

2. 顶部统计卡片
   - `专家总数`
     - 取真实专家总量
   - `进行中项目`
     - 按真实项目状态统计进行中项目数量
   - `技能领域`
     - 主值展示真实技能总量
     - 同时在卡片文案或副信息中体现真实领域总量
   - `匹配成功率`
     - 基于真实项目-专家关联关系计算
     - 公式固定为：`已至少分配 1 位专家的项目数 / 项目总数`
     - 若项目总数为 `0`，展示为 `--`
     - 若项目存在但分配关系为空，展示为 `0%`
     - 不使用写死值

3. 榜单与最近记录
   - `热门技能排行榜`
     - 基于真实技能数据排序
     - 排序优先级：`projectCount` > `expertCount` > `demandLevel`
     - `demandLevel` 归一化规则固定为：
       - `CRITICAL` -> 5
       - `HIGH` -> 4
       - `MEDIUM` -> 3
       - `LOW` -> 2
       - 其他或空值 -> 1
   - `最近匹配记录`
     - 优先由真实项目-专家关系生成
     - 排序字段固定为：
       - 优先 `assignment.startDate`
       - 若缺失，则回退 `project.updatedAt`
       - 再缺失则回退 `project.createdAt`
     - `matchScore` 不再使用随机分值
     - 若 `completionPercentage` 存在，则直接使用它作为匹配度展示值
     - 若 `completionPercentage` 缺失，则该列退化为状态标签列，不再展示分数
     - 不生成随机时间、随机匹配分
     - 若分配关系为空，表格显示空态 `暂无匹配记录`

4. 图表区
   - 保留现有四块图表布局
   - 用真实 ECharts 数据替换占位内容
   - `专家分布统计`
     - 支持按技能 / 状态 / 公司切换
     - 空公司统一归类为 `未填写公司`
   - `项目进度统计`
     - 支持按状态 / 预算区间 / 时长区间切换
     - 时长区间基于 `startDate` 到 `endDate` 计算
     - 若项目无 `endDate`，按“进行中项目”口径使用当前日期计算时长
   - `技能需求趋势`
     - 明确改名为 `技能需求分布`
     - selector 固定为：
       - `hot`: 技能热度分布
       - `demand`: 需求等级分布
       - `domain`: 所属领域分布
     - 不保留伪趋势含义
     - `timeRange` 对该图无效，仅保留 selector 切换
     - `demand` 分布同样使用固定归一化规则：
       - `CRITICAL / HIGH / MEDIUM / LOW / OTHER`
   - `匹配成功率趋势`
     - 明确改名为 `项目匹配分布`
     - selector 固定为：
       - `coverage`: 项目是否已匹配分布
       - `status`: 分配状态分布
       - `completion`: 分配完成度区间分布
     - 相关标题和切换项同步改成真实口径
     - `timeRange` 仅在分配记录存在日期字段时参与筛选，否则忽略

5. 页面状态与降级策略
   - 增加 `loading / error / empty` 三态
   - 若部分接口失败，页面优先展示已获取的真实数据
   - 依赖缺失数据的区块单独显示空态或降级提示，不让整页崩掉
   - `技能领域` 卡片在 `skills` 成功但 `domains` 失败时：
     - 主值仍展示技能总量
     - 副文案改为 `领域数据加载失败`

6. 真实边界约束
   - 可以做的近似：
     - 基于当前真实实体进行聚合、分类、排序、区间映射
   - 不允许做的近似：
     - 伪造历史月份趋势
     - 伪造随机增长率
     - 伪造随机匹配分
     - 伪造最近记录时间线
   - 状态映射固定为：
     - `进行中项目` 统计包含：`IN_PROGRESS`
     - 分配状态若存在 `ACTIVE`、`CONFIRMED`、`COMPLETED` 这类值，统一按真实值映射中文，不自行虚构新状态

7. 验证
   - 确认真实接口返回可支撑分析页展示
   - 页面联调时逐块核对：
     - 顶部卡片
     - 热门技能榜
     - 最近匹配记录
     - 4 个图表
   - 验证矩阵至少覆盖：
     - 每个卡片对应哪些源接口
     - 每个图表对应哪些源接口和聚合公式
     - 每个空态和降级文案在什么条件下触发
   - 抽查关键统计口径与源数据是否一致
   - 对改动文件运行诊断，确保不引入新的可见问题
