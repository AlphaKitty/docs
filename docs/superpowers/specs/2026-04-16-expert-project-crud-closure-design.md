# 专家与项目基础 CRUD 闭环设计

**目标**

补齐当前最基本的业务闭环：专家编辑、项目编辑，以及从专家详情页发起“匹配项目”并创建真实项目-专家分配关系。

**范围**

- 修改 `expert-link-frontend`
- 复用现有 `AddExpert.vue`、`AddProject.vue` 做新增 / 编辑双模式
- 补充专家侧真实匹配项目链路
- 本轮不新增独立 `ExpertEdit.vue` / `ProjectEdit.vue`
- 本轮不扩展复杂匹配算法，仅完成真实分配闭环

**设计**

1. 路由
   - 新增 `/experts/:id/edit`
   - 新增 `/projects/:id/edit`
   - 两条路由分别复用：
     - `AddExpert.vue`
     - `AddProject.vue`

2. 专家编辑
   - `AddExpert.vue` 改成双模式
   - 编辑模式根据路由参数加载真实专家详情并回填
   - 保存时调用真实更新接口，而不是本地占位逻辑
   - `ExpertList.vue` 和 `ExpertDetail.vue` 的编辑入口统一跳转到编辑路由

3. 项目编辑
   - `AddProject.vue` 改成双模式
   - 编辑模式根据路由参数加载真实项目详情并回填
   - 保存时调用真实更新接口
   - `ProjectList.vue` 和 `ProjectDetail.vue` 的编辑入口统一跳转到编辑路由

4. 专家侧匹配项目
   - `ExpertDetail.vue` 的“匹配项目”按钮改为真实弹窗或真实选择流程
   - 数据来源：
     - 项目列表来自真实项目接口
     - 当前专家 ID 来自详情页路由
   - 提交时调用现有项目-专家分配接口创建真实关系
   - 已分配过的项目不可重复分配
   - 分配成功后：
     - 专家页中的项目区域立即反映新关系
     - 项目详情页进入后也能看到该专家

5. 页面状态
   - 新增 / 编辑页增加加载和提交状态
   - 编辑模式下加载失败要提示，不允许静默回落到空白新增页
   - 匹配项目弹窗在无可分配项目时显示明确空态

6. 验证
   - 专家列表可进入编辑页并保存成功
   - 项目列表可进入编辑页并保存成功
   - 专家详情可发起真实项目匹配
   - 匹配成功后专家侧和项目侧都能看到关系
   - 不引入新的触达型前端诊断问题
